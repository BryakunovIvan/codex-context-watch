# Проверка версии 1.0.0

Проверено 4 октября 2026 года.

- 37 тестов стандартного unittest: прошли. Среди них — subprocess-тест
  настоящего curses-интерфейса через псевдотерминал.
- Ручной сценарий через псевдотерминал: все пять видов, поиск, просмотр,
  прокрутка, history/active, пауза, справка и выбор чата. Завершение с кодом 0.
- Проверка всех 136 локальных JSONL сессий: без исключений. Найдено 13 событий
  сжатия, повреждённых строк и записей с неверными типами полей не было.
  Неизвестные типы явно показаны в диагностике и не включаются в оценку текста.
- Отдельный обзор всего исходного кода проведён ревьюером с отдельным контекстом.
  Все четыре обнаруженные проблемы воспроизведены тестами и исправлены:
  неверные типы полей, диагностика в TUI, перезапись перед дописыванием,
  сохранение размера окна на момент измерения usage.
- Найденное при проверке старых логов замедление поиска Markdown-путей
  устранено: вместо регулярного выражения с возвратами используется разбор
  токенов shell-команды. Длинная команда и пути с пробелами покрыты тестами.

## Принятые решения и пределы проверки

- Утилита запускается непосредственно из своей папки. Установка в домашний
  каталог и изменения конфигурации Codex для запуска не требуются.
- Для фрагментов используется оценка UTF-8/4 с явной маркировкой `≈`.
  Риск: число отличается от токенизации модели; точные байты остаются доступны,
  а счётчик последнего запроса не подменяется оценкой.
- Точное восстановление скрытого prompt и непрозрачных блоков не заявлено.
  Риск: рейтинг описывает наблюдаемый текст, а не все составляющие запроса.
- Общий ответ нескольких вложенных вызовов не распределяется по скиллам.
  Риск: их связанные размеры перекрываются; интерфейс и README предупреждают
  об этом, а исходное содержимое доступно для просмотра.

Список неизвестных типов, встреченных при проверке старых логов:
`web_search_call`, `inter_agent_communication_metadata`, `agent_message`,
`tool_search_call`, `tool_search_output`, `realtime_item`.
Эти разновидности не мешают прочитать остальные записи. Для голосовых,
серверных и новых версий протокола детализация может быть неполной.
