# Проверка режимов списка файлов

Проверено 7 октября 2026 года на macOS с Python 3.14.

- `LC_ALL=en_US.UTF-8 python3 -m unittest discover -s tests -v`: все 55 тестов
  прошли. Новые проверки покрывают режимы `all`/`md`, расширение `.MD`,
  исключение `notes.md.bak` и файлов внутри каталога с суффиксом `.md`,
  сочетание режима с поиском, пустой список, `--top` и `active`/`history`.
- Настоящий curses через псевдотерминал: начальный режим `--files md`,
  переключения клавишей `m` в обе стороны, пустой список, просмотр вызова
  и выход. Тест экрана дополнительно проверяет сохранение режима при переходах
  между видами и `active`/`history`, поиск, сброс, прокрутку и маленький терминал.
- CLI-тесты проверяют оба режима `report` и `watch --plain --once`,
  текстовый вывод без TTY, сохранение полного списка в JSON и ошибочный режим.
- Отдельный запуск `watch --plain --once --files all` и `--files md`
  на временном синтетическом логе: три файла в первом режиме, два Markdown-файла
  во втором. `report --files md --json` сохранил все три файла.
- `python3 codex-context --help` и `python3 -m context_watch watch --help`:
  код 0; новый флаг отображается в справке. `git diff --check`: ошибок нет.

Режим ограничивает только список файлов в TUI и текстовом отчёте; JSON
сохраняет полный анализ. Ограничения распознавания операций остаются прежними.
Проверки использовали UTF-8-локаль и синтетические данные; Linux и Python 3.10
отдельно не запускались.

## Проверка вида «Файлы» до добавления режимов

Проверено 7 октября 2026 года на macOS с Python 3.14.

- `LC_ALL=en_US.UTF-8 python3 -m unittest discover -s tests -v`: все 52 теста
  прошли. Разбор файлов проверен на синтетических данных: чтение разных
  расширений, пробелы, многострочные команды, комментарии, аргументы `sed`/`rg`,
  перенаправления, вложенные вызовы, патчи и перемещения, динамические аргументы,
  нормализация путей и отдельные списки `active`/`history` после сжатия.
- Настоящий curses через псевдотерминал: клавиша `6`, вид файлов, создание,
  просмотр связанного вызова, возврат, диагностика и выход с кодом 0.
  Отдельный тест экрана проверяет PgDn, Home/End, поиск и его сброс,
  переходы стрелками, прокрутку просмотра, маленький терминал и выход;
  в нём цвета отключены для проверки текстовых отметок.
- Обе точки входа с `--help`: код 0.
- Отдельные `report --json` и `watch --plain --once` на временном синтетическом
  логе: три файла, чтение/изменение/создание/удаление, корректные связи и
  отсутствие поля полного текста в JSON по умолчанию. CLI-тест также проверяет
  `--full`, `inspect` и автоматический текстовый вывод без TTY.
- `git diff --check`: ошибок нет.

Первый запуск тестов без явной локали выявил `locale.Error` в существующем
запуске curses: локаль окружения не поддерживается этим Python. С установленной
UTF-8-локалью терминальные тесты прошли. Обработка локали приложения не менялась.

Реальные чаты для этой проверки не читались. Linux и Python 3.10 отдельно
не запускались. Операции файлов остаются предположениями по аргументам;
успех вызова, произвольные shell-записи и динамические пути не подтверждаются.
Визуальная оценка цветов в разных терминальных приложениях не проводилась.

## Историческая проверка версии 1.0.0

Проверено 4 октября 2026 года.

- 37 тестов стандартного unittest: прошли. Среди них — subprocess-тест
  настоящего curses-интерфейса через псевдотерминал.
- Ручной сценарий через псевдотерминал: все пять видов, поиск, просмотр,
  прокрутка, history/active, пауза, справка и выбор чата. Завершение с кодом 0.
- Проверка всех 136 локальных JSONL сессий: без исключений. Найдено 13 событий
  сжатия, повреждённых строк и записей с неверными типами полей не было.
  Неизвестные типы явно показаны в диагностике и не включаются в оценку текста.
- Отдельный обзор всего исходного кода проведён ревьюером с отдельным контекстом.
  Все четыре обнаруженные проблемы воспроизведены тестами и исправлены:
  неверные типы полей, диагностика в TUI, перезапись перед дописыванием,
  сохранение размера окна на момент измерения usage.
- Найденное при проверке старых логов замедление поиска Markdown-путей
  устранено: вместо регулярного выражения с возвратами используется разбор
  токенов shell-команды. Длинная команда и пути с пробелами покрыты тестами.

## Принятые решения и пределы проверки

- Утилита запускается непосредственно из своей папки. Установка в домашний
  каталог и изменения конфигурации Codex для запуска не требуются.
- Для фрагментов используется оценка UTF-8/4 с явной маркировкой `≈`.
  Риск: число отличается от токенизации модели; точные байты остаются доступны,
  а счётчик последнего запроса не подменяется оценкой.
- Точное восстановление скрытого prompt и непрозрачных блоков не заявлено.
  Риск: рейтинг описывает наблюдаемый текст, а не все составляющие запроса.
- Общий ответ нескольких вложенных вызовов не распределяется по скиллам.
  Риск: их связанные размеры перекрываются; интерфейс и README предупреждают
  об этом, а исходное содержимое доступно для просмотра.

Список неизвестных типов, встреченных при проверке старых логов:
`web_search_call`, `inter_agent_communication_metadata`, `agent_message`,
`tool_search_call`, `tool_search_output`, `realtime_item`.
Эти разновидности не мешают прочитать остальные записи. Для голосовых,
серверных и новых версий протокола детализация может быть неполной.
