# Codex Context Watch

Локальная утилита, показывающая, **какие записи раздувают наблюдаемую историю
Codex**: инструкции, сообщения, аргументы вызовов, ответы инструментов и чтения
скиллов, а также предполагаемые обращения к файлам. Работает с логами Codex CLI
и локальными чатами приложения, которые записываются в `~/.codex/sessions`.

Python **3.10+**, macOS или Linux, только стандартная библиотека. Установка пакетов и API-ключ
не нужны. Утилита не обращается в сеть и не меняет настройки или логи Codex.

## Быстрый запуск

Склонируйте репозиторий и запустите утилиту:

```sh
git clone https://github.com/BryakunovIvan/codex-context-watch.git
cd codex-context-watch
python3 codex-context watch
```

Из каталога утилиты также можно запустить:

```sh
./codex-context watch
```

На macOS можно дважды щёлкнуть `Launch Watch.command`. Откроется Terminal
с монитором самой свежей сессии. Нажмите **s**, чтобы выбрать нужный чат.

При запуске из другого каталога укажите путь к исполняемому файлу:

```sh
python3 /полный/путь/codex-context/codex-context watch
```

Чтобы выбрать чат по ID, сначала выведите список сессий:

```sh
./codex-context sessions
./codex-context watch --session SESSION_ID
```

Замените `SESSION_ID` на ID из списка или его уникальный префикс.

Watch остаётся привязан к выбранному чату. Активность другого чата сама
по себе не переключает монитор. Данные обновляются раз в 0,75 секунды.

## Управление

| Клавиша | Действие |
| --- | --- |
| `1`–`6`, `←` / `→` | Крупнейшие записи / инструменты / скиллы / категории / события / файлы |
| `↑` / `↓`, `j` / `k` | Выбор записи |
| `PgUp` / `PgDn`, `Home` / `End` | Перемещение по списку |
| `Enter` | Полное содержимое; для инструмента/скилла/категории/файла — связанные записи |
| `/` | Поиск по полному содержимому, названию инструмента или пути файла/скилла |
| `c` | Сбросить поиск |
| `h` | Переключить `active` / `history` |
| `m` | В виде «Файлы»: все файлы / только `.md` |
| `s` | Выбрать другой чат |
| `p` | Пауза обновления |
| `?` | Справка |
| `d` | Диагностика неполных, неизвестных и повреждённых данных |
| `q` | Выход; в просмотре содержимого — назад |

Для TUI нужен терминал минимум 72×14 символов. Без интерактивного терминала,
или с флагом `--plain`, выводятся текстовые снимки при изменении данных.

## Что означают числа

**Последний запрос: вход / выход / кэш** — значения из `token_count` или
`token_usage_record`. Вход / размер окна даёт долю окна **на момент того
запроса**. Это не точное измерение контекста в каждую секунду. Вход уже включает
кэшированные токены: прибавлять кэш к входу нельзя. Отсутствующие значения
показаны как `—`, а не ноль. Метрика до последнего сжатия помечается отдельно.

**Накопленный вход всех запросов** — повторная обработка контекста за весь чат.
Он может сильно превышать размер окна. Сумма включает кэшированный вход;
она показывает объём обработки, а не текущую заполненность или денежную стоимость.

**Байты / символы** — точный размер извлечённого видимого текста. Структура
сообщений, служебная упаковка, схемы инструментов и токены медиа сюда не входят.
Это наиболее надёжная величина для сравнения отдельных записей.

**≈ токенов** — грубый вес `ceil(UTF-8 bytes / 4)` для каждого фрагмента.
Это **не токенизация модели**: русский текст, код, JSON и разные модели могут
давать другие числа. Эту оценку нельзя считать точной разбивкой счётчика запроса.
Непрозрачные зашифрованные рассуждения и блоки сжатия, base64 изображения,
аудио и файлы не превращаются в фиктивные текстовые токены.

`active` показывает записи наблюдаемой истории после последнего сжатия:
если в логе есть `replacement_history`, используется этот снимок. Если его нет,
восстановление помечается как частичное. Базовые инструкции из метаданных
показаны отдельно; лог не доказывает их фактическое включение в каждый запрос.
Это анализ локального лога, а не гарантированная копия текущего запроса модели.

`history` показывает исходные записи за всё время сессии. Снимки истории при
сжатии не добавляются в этот рейтинг повторно. **Размер history не означает
текущий контекст.**

## Как найти причину роста

1. Откройте вид **1 Размер** и просмотрите самые большие записи через Enter.
   Будут видны номер строки JSONL, ID вызова, инструмент и полный текст.
2. Вид **2 Инструменты** группирует аргументы и ответы. Вложенные вызовы
   `tools.exec_command`, `tools.web__run` и т. п. извлекаются из кода `exec`.
   Они помечены как предположение: наличие вызова в коде не доказывает его
   выполнение, число блоков не равно числу фактически выполненных вызовов.
3. Вид **3 Скиллы** ищет пути `SKILL.md` в командах чтения и файлы
   `/skills/<skill>/references/*.md`. Это связь с предполагаемым чтением,
   а не гарантия успешной загрузки. Простое упоминание пути внутри записываемого
   кода или патча не считается чтением скилла.
4. Если один `exec` читает несколько скиллов или вызывает другие инструменты,
   его общий ответ показывается рядом с каждым связанным скиллом/инструментом.
   **Эти значения перекрываются, их нельзя складывать.** Точное распределение
   общей выдачи между вложенными вызовами из лога не восстанавливается.
5. Вид **5 События** позволяет посмотреть последовательность записей и сжатия.
   Для анализа старой причины роста переключитесь на `history` клавишей `h`.

## Какие файлы затрагивал Codex

Нажмите **6**, чтобы открыть вид **Файлы**. Он показывает пути и предполагаемые
операции из аргументов инструментов, в том числе вложенных вызовов в `exec`:

- **Чтение** — буквальные пути в командах `cat`, `sed`, `head`, `tail`, `less`,
  `more`, `rg`; цвет голубой. Для `rg` путь может быть каталогом поиска.
- **Создание** — `*** Add File` в `apply_patch`; цвет зелёный.
- **Изменение** — `*** Update File`; цвет жёлтый.
- **Удаление** — `*** Delete File`; цвет красный.
- **Перемещение** — `*** Move to`, с отдельными путями источника и назначения;
  цвет жёлтый.

Клавиша **m** переключает два режима: **все файлы** (по умолчанию) и **только
`.md`**. Расширение проверяется без учёта регистра: `.MD` тоже включается,
а `notes.md.bak` и файлы других типов внутри каталога `docs.md` — нет.
Текущий режим виден над списком и сохраняется при поиске, переходе между
видами, смене чата и переключении `active` / `history` до выхода из монитора.
Режим ограничивает список файлов, не меняя общие счётчики или другие виды.

Если у файла несколько операций, видны все отметки; цвет выбирается в порядке
удаление, изменение/перемещение, создание, чтение. В терминале без цветов
отметки остаются текстом, операции изменения выделены жирным.

По **Enter** открываются связанные аргументы вызовов и ответы: можно проверить,
не завершился ли инструмент ошибкой. Число блоков учитывает вызов один раз на
файл, без повторного счёта ответа; несколько вложенных вызовов внутри одного
`exec` остаются одним блоком. Размеры текста и токенов по файлам не распределяются.

Относительные пути объединяются с `cwd` сессии/хода или `workdir` команды,
когда эти значения доступны в логе. При неизвестном каталоге путь остаётся
относительным. Нормализация не читает файловую систему и не разрешает симлинки.
Поиск по пути отбирает соответствующие файлы; если совпадений по пути нет,
используется полный текст связанных записей. Общие счётчики не меняются.
Клавиша **h** переключает список между `active` и `history`, как другие виды.

Это **предположение по аргументам**, а не подтверждение выполнения или успеха
операции. Упоминания путей в чате или внутри записываемого кода не учитываются.
Произвольные shell-команды записи, Python-скрипты, подстановки, переменные,
glob-пути, heredoc, команды с `cd` и динамические аргументы не восстанавливаются.
Команды `sed -i` не классифицируются как простое чтение. Поэтому список может
быть неполным; полный аудит изменений файлов по JSONL не гарантируется.

В текстовом `report` и `watch --plain` есть раздел **Файлы**, ограниченный
`--top`. Флаг `--files md` оставляет в этом разделе только Markdown-файлы;
`--files all` показывает все файлы. В TUI флаг задаёт начальный режим.
JSON при любом режиме содержит полный список `files` с операциями, числом блоков и
`entry_ids`; записи содержат `file_accesses`. Эти поля доступны без `--full`.

## Команды и экспорт

```sh
# Доступные чаты; можно скопировать ID.
./codex-context sessions
./codex-context sessions --archived --limit 100

# Статический отчёт, крупнейшие 20 записей.
./codex-context report --session SESSION_ID --top 20
./codex-context report --session SESSION_ID --scope history
./codex-context report --session SESSION_ID --filter context_watch/analyzer.py
./codex-context report --session SESSION_ID --files md

# JSON: размеры, связи и метаданные; без полного содержимого по умолчанию.
./codex-context report --session SESSION_ID --json > report.json
./codex-context report --session SESSION_ID --json --full > full-report.json

# Конкретная запись и точная строка в исходном логе.
./codex-context inspect --session SESSION_ID --item e000012
./codex-context inspect --session SESSION_ID --scope history --item e000012 --json

# Лог по явному пути; другой каталог данных Codex.
./codex-context watch --file /путь/rollout.jsonl
./codex-context watch --file /путь/rollout.jsonl --files md
./codex-context watch --home /путь/.codex

# Текстовый watch или JSON Lines для других утилит.
./codex-context watch --session SESSION_ID --plain --filter SKILL.md
./codex-context watch --session SESSION_ID --json --interval 1
./codex-context watch --session SESSION_ID --once
```

`CODEX_HOME` поддерживается; явный `--home` имеет приоритет. Названия чатов
читаются из `state_*.sqlite` в режиме только чтения. При отсутствии или
недоступности базы утилита работает по JSONL. Поиск использует полный текст
записей, даже когда в списке виден только короткий фрагмент. Фильтр не меняет
общие счётчики; в JSON сохраняется вся выбранная история.

ID `e000012` устойчив для неизменного лога, но не является ID Codex.
При перезаписи исходного файла утилита перечитывает его.
При изменении файла дополнительно проверяется SHA-256 уже прочитанной части:
это обнаруживает перезапись ранних записей вместе с дописыванием новых. Старые
байты читаются для проверки, а JSON разбирается повторно только при перезаписи.
Неполная последняя строка остаётся в буфере до появления перевода строки. Повреждённые полные
строки пропускаются с явным счётчиком. Типы событий, которые парсер не знает,
отображаются как неизвестные и не получают выдуманную оценку.

Полный JSON и содержимое записей могут включать текст вашего чата и результаты
инструментов. Экспорт идёт только в указанный вами файл, без отправки наружу.

## Проверка

```sh
python3 -m unittest discover -s tests -v
```

Тесты используют синтетические логи. Проверяются разные схемы usage,
переход после сжатия, отсутствие двойного учёта event-проекций, пути скиллов,
вложенные вызовы, чтение и операции файлов, частичные UTF-8 строки, перезапись/замена файлов, поиск,
JSON-экспорт, выбор чата и обновление watch без самопроизвольного переключения.
